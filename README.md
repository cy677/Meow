# Meow · 小猫成长花园

面向 **3—10岁儿童家庭**的本地积分宠物。孩子在现实生活中完成事先约定的小行动，由家长记录具体理由；喵币用于兑换小猫外观、猫窝、木地板、玩具和家长创作的完整作品。

儿童首页直接运行原版 Three.js 小猫，保留触摸、软体互动、14个原版动作素材及原有场景；孩子动作改为自动随机脚本，特殊动作与姿态按积分解锁。新增加分体系围绕六个并列成长分类展开，不把孩子的能力或心理健康变成分数排名。

**所有积分、理由、奖励预设、兑换和成长记录保存在运行服务的电脑上的 SQLite 文件。** iPad浏览器访问同一个本地服务，不以浏览器缓存作为账本，不上传到GitHub或云端。

## 启动与iPad访问

需要 **Node.js 22.16.0或兼容的更新版本**、npm、支持WebGL的浏览器。初次安装依赖需要联网，构建后使用不需要外部模型或云端服务。

```bash
git clone https://github.com/cy677/Meow.git
cd Meow
npm ci
npm run pet:build
npm run pet:lan
```

在电脑终端查看打印的局域网地址，例如 `http://192.168.1.100:8792`，让iPad与电脑处于同一可信局域网，用浏览器打开该地址。默认端口8792；首次初始化口令在终端打印，不能当作孩子进入码分享。

首次访问家长页面 `http://电脑IP:8792/parent.html`，设置家长密码、不同的孩子进入码、昵称、小猫名字，**填写孩子周岁并确认成长模式**。6岁时可补充入学情况；系统推荐模式，但由家长决定。不要求真实姓名或完整出生日期。

Windows首次运行可能需要允许Node通过专用网络防火墙。服务电脑需要保持运行。不把家长界面或端口直接暴露到互联网。局域网HTTP不加密，HTTPS和陀螺仪配置参见 [平板部署说明](pet/PAD.md)。本次改造未新增相机、麦克风或大模型联网服务。

其他启动命令：

```bash
npm run pet:start      # 只在本机使用
npm run pet:dev        # 积分应用开发服务
npm run pet:lan:https  # 配好受信任证书后使用
```

`npm run dev` / `npm run build` 仍对应原版静态编辑器，不是带SQLite的家庭积分服务。GitHub Pages不能运行本地Node服务和家庭账本。

## 三种成长模式

| 模式 | 参考阶段 | 项目与界面 |
| --- | --- | --- |
| 学前模式 | 3—6岁，主要面向尚未入学的儿童 | 一次一个小步骤，允许示范和共同完成；大图标、成长回忆，家长记录 |
| 学龄基础模式 | 6—8岁参考 | 简短流程、学习准备、同伴合作与家庭责任；可提交完成情况等待家长确认 |
| 学龄进阶模式 | 9—10岁参考 | 目标选择、任务拆分、检查与协商；支持多日小项目及分步记录 |

年龄建议不是能力门槛。修改年龄不会自动更换模式；模式切换只更新推荐和展示方式，**不清空积分、记录、收藏，也不自动替换已启用目标和进行中的项目**。家长可继续选用其他模式的合适项目。

项目库包含 **66个预设**：学前30个、学龄基础18个、学龄进阶18个。初始化不强制启用目标；建议先选1—2个，进阶模式可选2—3个。不要求每日六类打卡。

## 六类与家长加分依据

| 主分类 | 儿童名称 | 归类范围 |
| --- | --- | --- |
| 健康活力 | 活力喵 | 运动、卫生、饮食认知、睡前准备、安全和用屏习惯 |
| 情绪与自我 | 心情喵 | 自愿表达感受、求助、调节方法、自我认识与挫折应对 |
| 交往与关爱 | 友爱喵 | 倾听、合作、关爱、协商和个人边界 |
| 自理与责任 | 能干喵 | 自理、整理、家务、履行约定与失误补救 |
| 学习与探索 | 好奇喵 | 阅读、观察、提问、学习方法、尝试和检查 |
| 创意与审美 | 创意喵 | 绘画、音乐、手工、故事、想象游戏和欣赏 |

这六类**并列、不分高低**。按照本次主要鼓励的行动选一个主分类，同一行动只记一次。家长可按模式筛选项目、查看其他模式、新增或修改自定义项目，使用普通表单，无需编辑JSON。

加分页已移除家长示例提示和理由示例。选择项目库项目时展示其完成条件，填写具体理由；自定义单次行动只必填行动标题，不要求详细理由或自定义分值的调整理由，流水直接使用标题。

| 分值 | 加分依据 |
| --- | --- |
| ＋1 小步尝试 | 事先约定只尝试一个很小的步骤 |
| ＋2 日常行动 | 完成一个清楚、适龄的日常行为；自定义项目默认值 |
| ＋3 投入练习 | 完成一段活动，或尝试解决一个问题 |
| ＋5 特别进步 | 相对孩子自身起点的明显进步，或事先约定的小挑战 |
| 0 仅记录 | 留下成长回忆，不增加喵币与经验 |

改变默认分值时，需要填写事先约定的依据。**成人提醒、清单、示范、共同完成或求助不自动减分。** 不以成绩排名、吃光、立刻睡着、保持开心、不哭、服从或公开隐私作为默认奖励条件。安慰、安全与基本照护不需积分兑换。

完整项目表、操作示例、研究来源和适用边界见 [家长加分指南](pet/GROWTH_GUIDE.md)。这些分类、项目和分值是产品配置，不是指南规定的评分表、发育达标线或心理筛查。

## 目标、记录和确认

家长在“日常加分 → 目标与项目库”启用少量目标，可暂停或归档。未启用项目不显示失败或缺勤。可以从项目库记录自然发生的行动，也可选择自定义单次行动。

普通项目默认每天最多计分一次，可事先配置1—4次，或设为只记录一次。按家长档案中的家庭时区确定记录日期；行动时间和录入时间分别保存。计分频次不是刷牙、运动等行为的健康推荐频次。

学龄孩子可点击“我完成了”，说明可留空，不需要提交照片或隐私。这只产生待确认记录，**只有家长核对并确认后才入账**。待确认内容保存提交时的规则快照；之后修改项目或切换模式不会偷偷改变已提交约定。

多日项目通过表单设置最多12个步骤，各步骤采用相同分值档位，按步骤分别记录，不能再次领取项目总分。暂停保留已完成步骤；已有记录的项目需要改变步骤时，请复制为新项目。

记录支持按类型、日期游标、理由文字、六类筛选，完整记录均可查询。家长的7天/30天统计只是“家庭成长记录分布”，不是能力评估。儿童端使用3×2等大成长卡片、贴纸和每页5条回忆；缺少记录的分类不会变灰或枯萎。

## 喵币与小猫奖励

- **喵币余额**用于兑换，购买后减少。
- **累计成长经验**保留获得记录，不因兑换减少。
- **六类成长记录**保存具体行动和当时规则，不因兑换删除。

默认每加1分，同时获得1枚喵币和1点成长经验。新增2枚喵币、无经验门槛的“薄荷小眼睛”，让一个普通小目标即可兑换首份小礼物。原有奖励ID、家长自定义价格、解锁门槛和所有权不被批量重置。

家长可在“奖励预设 → 生成奖励 / 参数面板”调整花色、体型、眼睛、姿态、场景和原版参数，保存为固定作品。预览和草稿不修改孩子当前小猫；兑换得到保存的参数快照，不重新随机。兑换价格与累计经验门槛分别设置。旧版目录的逐步揭晓、原版免费功能和场景装备规则继续保留。

已兑换物品重复使用不再次收费。基本小猫、基础随机动作、抚摸、拍照、音乐、光照和天气保持免费。特殊动作与姿态在收藏小屋按积分解锁；GLB/Codex 导出只在家长创作页提供，孩子页面不设家长入口。没有登录、未完成目标或情绪不好，不会导致小猫挨饿、生病、离开或扣分。本轮未实现语音模型、相机合影或心理自动判断。

## 旧版本升级与备份

**升级前停止服务，复制整个 `pet/data/` 目录作备份**；自定义数据库路径也应完整备份。首次打开旧库时增量添加字段与成长表，不删除原表，不推测年龄，不把原流水擅自归入六类，不重复发币，也不重定价旧奖励。

旧用户登录家长页面后补充年龄和模式；儿童仍能使用已有小猫和收藏。旧加分在“待归类旧记录”中由家长逐条核对、填写依据。归类只增加分类信息，不改变原时间、金额或余额。

误录更正必须关联一条原成长记录并说明原因，不是惩罚性扣分。原记录、更正原因和审计保留；余额不足时拒绝更正，不透支或自动回收已拥有物品。累计经验与已经解锁的权益保留；被更正记录不计入成长分布。

家长页可导出完整JSON记录（不包含密码或会话）。**JSON是可查阅导出，不提供自动导入恢复**；灾难恢复应在停止服务后恢复此前完整的SQLite数据目录。关闭网页或清理浏览器缓存不会删除服务端数据。

旧的 `/api/parent/points` 保留用于现有本地客户端兼容，仍属于独立的旧账本操作，不会猜测成长分类。新版页面不调用它，也不提供任意负分输入；新功能使用带分类、依据、版本和频次校验的成长接口。仅向可信家长客户端授予家长凭据。

## 数据与代码结构

| 路径 | 作用 |
| --- | --- |
| `pet/growthCatalog.mjs` | 三种模式、六类、66个示例、分值依据和官方来源说明 |
| `pet/growthStore.mjs` | 年龄与目标、快照、日限、待确认、分类与更正事务 |
| `pet/growthUI.js` / `pet/growth.css` | 家长加分与项目表单、儿童成长花园 |
| `pet/localLedger.mjs` | 原账本的增量迁移、分类查询和历史依据 |
| `pet/store.mjs` / `pet/server.mjs` | SQLite账本、奖励、会话、角色、CSRF与本地服务 |
| `pet/tests/growth.test.mjs` | 规则、迁移、并发幂等和HTTP权限测试 |
| `pet/tests/browser-growth.mjs` | 初始化、家长加分、孩子提交与成长花园真实浏览器回归 |
| `pet/tests/browser-creation.mjs` | 当前原版首页、家长作品、参数与导出回归 |
| `src/`、`public/` | 原版小猫实现和素材，保留原有署名与许可 |

请求在服务端执行权限、会话、CSRF、字段和分值验证。加分、兑换、完成状态与幂等请求放入事务；重复网络请求不会重复增加或扣除积分。系统不能自动判断两段不同文字是否描述同一次现实行动，家长仍须避免重复登记。

## 测试

```bash
npm run test:pet
npm run pet:build
npm run build
# 独立测试环境安装浏览器测试工具，不修改锁文件
npm install --no-save --package-lock=false --ignore-scripts playwright@1.55.0
npx playwright install chromium
node pet/tests/browser-growth.mjs
node pet/tests/browser-creation.mjs
```

测试数据使用临时库，不包含家庭真实记录。`Points pet checks`采用当前原版首页回归和成长流程回归；旧的独立小屋浏览器脚本仍保留作历史参考，部分旧选择器不适用于当前原版iframe首页。测试通过不等于真机Safari认证，iPad触摸和系统权限仍需在实际设备复核。
