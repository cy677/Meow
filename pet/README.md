# Meow 积分小猫（本地版）

一户家庭、一个孩子的积分宠物。新增功能集中在 `pet/`，直接复用原作 `src/catBuilder.js` 的三维小猫，不修改原编辑器。家长记录理由并加分，孩子用积分解锁、兑换和使用奖励。

## 数据全部保存在哪里

**积分余额、累计成长积分、每次加分理由、兑换流水、已拥有奖励、当前装扮和家长设置的参数预设，全部保存在运行服务的电脑本地文件 `pet/data/pet.sqlite`。**不是浏览器缓存，不依赖云端账户，不自动上传到 GitHub 或其他服务。正式启动使用磁盘数据库；内存数据库仅供自动化测试。

关掉页面、重新登录、清理浏览器数据或重启服务不会清除进度。家长页“记录与设置”会显示实际数据库路径；`MEOW_DATA_DIR` 指定自定义目录时也显示真实路径。孩子的平板访问同一服务，数据仍在家长电脑，不会在两台设备上各记一套。

首次创建数据库时从 `rewards.json` 读取初始目录。之后以本地数据库为准，重启不会用初始 JSON 覆盖家长设置。

## 启动与更新

需要 Node.js 22.16 或更高版本。在仓库根目录执行：

```sh
npm ci --ignore-scripts
npm run pet:build
npm run pet:start
```

孩子页面：`http://localhost:8792/`。家长页面：`http://localhost:8792/parent.html`。

首次启动终端打印一次性初始化口令。家长输入口令，设置自己的 6–12 位数字密码、孩子的 4–12 位数字进入码及昵称。没有默认密码，两种码不能相同。家长会话 15 分钟后过期；把同一浏览器交给孩子前请主动锁定家长页。

已有用户更新代码后，保留原 `pet/data/`，重新构建并启动即可。数据库迁移是增量的，不删表、不清积分、不重置预设。不要用 `git clean -fdx` 清理工程，否则会删除被忽略的数据目录。

开发模式：`npm run pet:dev`。原编辑器仍是 `npm run dev`，默认端口 8791，互不接管。

同一家庭网络中的其他设备使用家长电脑 IP 访问。Windows PowerShell：

```powershell
$env:MEOW_HOST="0.0.0.0"
npm run pet:start
```

打开 `http://家长电脑局域网IP:8792/`，输入孩子进入码。默认只监听本机。主机需要保持服务运行；HTTP 只用于可信家庭网络，不要直接映射到公网。公网访问需要 HTTPS 反向代理和 `MEOW_ORIGIN=https://你的域名`，保留对应 Host。`MEOW_PORT` 可改端口。积分版需要常驻 Node 服务，不能只放在 GitHub Pages 上运行。

## 加分必须填写理由，历史随时可查

家长页“日常加分”填写理由和分值后保存。空值、空格、缺失理由在页面及服务端都不能通过。常用理由按钮只是辅助填写，不会自行加分。负数用于更正余额，也必须写明原因，且不能透支。

家长的“积分理由与兑换记录”、孩子的“成长记录”都支持按理由或兑换名称查询，按加分、更正、兑换、礼物和预设修改筛选，点击“加载更早记录”继续查看。不是仅能查看最新 100 条；记录全部保留在本地。

新发生的兑换与成长礼物还保存**当时的奖励名称、价格、门槛和参数快照**，展开记录即可查看。以后重命名或修改预设不会改写旧记录。旧版本的历史只有原理由、奖励 ID 和时间，升级时保留原记录并注明当时参数未保存，不用当前配置冒充历史。

## 家长可视化预设编辑器

进入“奖励预设”，点击“新增奖励预设”；已有奖励旁的“调参数”用于修改，“复制”用于另建一项奖励。不需要手写 JSON。

| 类别 | 可调内容 |
| --- | --- |
| 花色 | 原作基础花色；开启自定义配色后调整底色、主色、辅助色，以及对应类型的色块/身体条纹/头部条纹参数 |
| 体型 | 头部大小、圆润程度、腿长、耳朵、尾巴长度和卷曲、蓬松毛发 |
| 眼睛 | 眼睛颜色、异瞳、大小、眼距、瞳孔、高光、水汪汪效果 |
| 姿态 | 原作已有的站立、面包、伸懒腰、双足、岔腿坐、侧卧和香蕉造型 |
| 互动动作 | 跳跃或转圈；动作时长、跳跃高度或转圈圈数 |

右侧实时三维预览使用默认小猫叠加当前类别参数，不修改孩子的装扮、不扣积分。动作有“试播”按钮。输入奖励名称、说明、解锁积分和兑换费用后，点“保存到本地”才真正写入。取消或关闭未保存草稿不会改变数据库；关闭时会提示放弃草稿。

“解锁所需累计积分”决定门槛。“兑换消耗积分”决定实际扣款：

- 累计门槛 50、兑换费用 0：累计获得 50 分时自动解锁，不扣积分。
- 累计门槛 50、兑换费用 20：达到 50 分后开放兑换，孩子确认时消耗 20 分。

已兑换奖励永久拥有，不会重复收费。**累计成长积分**不因消费或余额更正减少；**可兑换余额**随消费减少。没有饥饿、死亡、断签惩罚或随机抽奖。

修改已有预设保留稳定 ID、类别和初始标记；价格调整不重新扣款，孩子已有的拥有权不回收。如果修改了孩子正在使用的预设，其当前外观会更新；历史兑换快照保持原样。两个家长页面并行编辑时，旧版本提交会被拒绝，草稿保留，避免覆盖另一页面的新设置。

初始目录有 20 项奖励（含 4 项免费初始配置）。体型参数使用温和范围；跳跃/转圈是整体变换互动，尚未接入原作全部 Mesh2Motion 骨骼动画，也不包含随机猫窝。新增已有参数组合可用表单或 JSON；全新造型/动画仍需扩展渲染器和参数白名单。

## JSON 导入导出与外置接口

JSON 是可选的批量配置方式，不再是创建预设的必经步骤。完整目录格式为 `{ "schemaVersion": 1, "rewards": [...] }`。示例奖励：

```json
{
  "id": "my-round-kitten",
  "title": "圆圆小团子",
  "description": "家长为你制作的小猫",
  "category": "shape",
  "cost": 20,
  "unlockAt": 50,
  "params": { "chubbiness": 1.7, "legLength": 0.65 }
}
```

单项互动示例：`{ "id":"my-spin", "title":"慢慢转两圈", "description":"小猫转圈互动", "category":"trick", "cost":10, "unlockAt":30, "action":"spin", "motion":{"duration":2.4,"turns":2} }`。

`presetSchema.mjs` 同时驱动家长表单与服务端校验，拒绝不支持的字段、越界参数、任意代码/URL和原型字段。

| 方法与路径 | 权限 | 用途 |
| --- | --- | --- |
| GET `/api/status` | 无 | 仅返回是否已初始化 |
| POST `/api/parent/setup` | 一次性口令 | 初始化凭据及昵称 |
| POST `/api/parent/login`、`/api/child/login` | 相应密码 | `{code}` 登录 |
| GET `/api/parent/session`、`/api/child/session` | 相应会话 | 读取 CSRF、到期时间与状态 |
| POST `/api/parent/logout`、`/api/child/logout` | 相应会话 | 注销并吊销令牌 |
| GET `/api/parent/state`、`/api/state` | 家长、孩子 | 积分、拥有权、当前装扮 |
| POST `/api/parent/points` | 家长 | `{delta, reason, idempotencyKey}`；理由必填 |
| GET `/api/parent/history`、`/api/history` | 家长、孩子 | `q` 理由子串、`kind` 类型、`limit` 每页 1–100、`before` 游标；返回 `entries,total,nextCursor` |
| GET `/api/parent/storage` | 家长 | 本地保存路径、持久化状态、记录数 |
| GET `/api/parent/presets` | 家长 | 完整目录和 `revision` |
| PUT `/api/parent/presets` | 家长 | `{reward, expectedRevision}`；新建或更新单个预设 |
| GET/PUT `/api/parent/catalog` | 家长 | 读取或保存整个目录；写入可加 `If-Match: <revision>` 防止覆盖旧版本 |
| PUT `/api/parent/profile` | 家长 | `{childName,petName}` |
| PUT `/api/parent/credentials` | 家长和当前密码 | `{currentPin,newPin?,childCode?}` |
| GET `/api/parent/export` | 家长 | 完整流水、状态及目录，不含密码 |
| POST `/api/purchase` | 孩子 | `{rewardId,expectedCost,idempotencyKey}` |
| POST `/api/equip` | 孩子 | `{rewardId}` 使用已拥有装扮/姿态 |
| POST `/api/play` | 孩子 | `{rewardId}`，返回已核验的动作与可选 `motion` 参数 |
| GET `/api/pet/config` | 孩子 | 当前参数、槽位和允许动作 |

写请求使用 `Content-Type: application/json`、`X-Meow-Client: points-pet`；除登录、初始化外，还要保留登录 Cookie 并提供 `X-CSRF-Token`。外部程序使用 Cookie jar 接入；浏览器默认拒绝跨站请求。

每次新的加分/购买使用新的 UUID 作为 `idempotencyKey`，超时重试沿用同一 ID 和内容。积分、拥有权、流水与请求去重在同一 SQLite 事务中提交。服务器按本地目录价格扣款，`expectedCost` 只核对用户确认的价格，不能指定优惠价。预设编辑器和价格表写入均带目录版本；发生 409 冲突时保留草稿并读取最新目录再检查。

## 备份与安全边界

完整备份：**停止服务后**复制整个 `pet/data/`（或 `MEOW_DATA_DIR`）目录。恢复前先备份当前目录，再用备份替换并启动。家长页导出的 JSON 是可查阅的审计记录，没有实现自动恢复导入，不代替完整数据库备份。

密码以随机盐 scrypt 哈希保存；家长与孩子会话独立、检查过期，修改密码会吊销对应角色旧会话。Cookie 使用 HttpOnly、SameSite；登录限速，写接口校验 CSRF 和角色。生产静态服务只开放构建目录，数据库及源码不作为静态资源暴露。默认本地数据、构建产物、测试数据已加入忽略规则。不要把真实孩子的数据、数据库或凭据提交到公开仓库。

前端开发工具可以改变本地视觉画面，但不能借此修改后台真实积分或拥有权。不要把仍保持家长登录的浏览器直接交给孩子使用。

```sh
npm run test:pet
npm run pet:build
npm run build
```

领域与 HTTP 测试覆盖理由必填、全部历史分页、旧库迁移、参数校验、版本冲突、兑换快照、重启后的积分/预设/拥有权保存和角色隔离。Actions 另外运行 `tests/browser.mjs` 与 `tests/browser-presets.mjs`，测试家长新建花色/体型/眼睛/姿态/互动、真实三维预览、保存/取消、孩子兑换/使用、刷新和新浏览器登录、理由查询、历史详情、手机布局及零外部运行时请求。是否通过以实际测试结果为准。
