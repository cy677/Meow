# 摄像头合影

## 使用方式

儿童页“拍照 · 留影”旁边就是“与我合影”。点击后开启摄像头并进入铺满页面的取景画面，不显示纪念卡边框。第一次使用需允许摄像头权限。默认优先前置镜头，授权后检测到多个摄像头才显示“切换前后摄像头”。前置默认镜像，镜像仅改变真人画面，不反转小猫。

单指拖动移动小猫，双指张合或“放大 / 缩小”按钮调整小猫大小，缩放按钮下方的“左转 / 右转”每次将小猫转动 15°；“还原构图”恢复本次初始视角和朝向。点击“拍照”直接使用原来的 PNG 文件保存流程，不再增加 iPad 保存按钮或二次预览保存步骤。合影 PNG 使用完整画布尺寸和比例，不带卡片边框；普通纪念卡仍输出 1200×1600 PNG。文件保存位置由浏览器和设备设置决定，并不等于直接写入系统相册。

拍完仍可继续构图和拍摄。点击“取消”退出拍照并恢复进入前视角；“退出合影”返回普通纪念卡模式。

## 数据与生命周期

照片只在本机内存中生成，通过浏览器下载保存，不上传、不写服务端数据库，也不建立网页相册。积分、装备、奖励及成长记录不受拍照影响。合影不使用麦克风。

关闭、退出合影、切到后台、离开页面、WebGL 丢失和设备中断时停止摄像头。回来后由用户重新开启。未完成的权限请求如在退出后才获准，其迟到视频轨道也会立即停止。切换镜头先释放旧镜头，退出恢复临时构图和场景状态。

## 实现

`src/shareCard.js` 管理纪念卡与全画面合影导出，两者统一调用原始 `downloadBlob` 保存。`photoMode.js` 管理合影状态、缩放与镜头控件；`deviceCamera.js` 管理授权、有效首帧、取消、超时和视频轨道释放；`photoSession.js` 复用现有 Three.js 相机和小猫。

视频纹理仅在渲染回调内替换房间背景与雾效，结束后恢复，避免影响天气模拟。控件不进入导出画布。全屏是页面取景铺满可用视口，不依赖设备的浏览器 Fullscreen API。家庭页的嵌入场景在合影时也铺满页面，退出后恢复原布局。

## HTTPS 和权限

摄像头需要浏览器信任的 HTTPS（本机 localhost 开发环境除外）。儿童页与同源场景 iframe 均须允许 camera；反向代理不得额外禁用该权限。首次使用仍由浏览器请求摄像头授权。无可用摄像头、拒绝权限或启动失败时显示错误并允许重试。

## 验证范围

设备生命周期与裁切使用 Node 测试，浏览器回归使用隔离的内存家庭和模拟摄像头，检查入口、页面全屏、缩放、镜头切换、完整 PNG 下载、退出恢复和无照片上传。模拟浏览器不等于真实 iPad 硬件验证；实体设备的镜头选择与保存位置取决于浏览器和系统。
